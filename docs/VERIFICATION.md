## 3. 内部恒等式校核（不依赖任何稿件文字）

对 21 城主结果逐城校核：

- **F₂ 分解恒等式** `F₂ = 0.2·A₁ + 0.3·S₂ + 0.5·0.6·cov`：21 城两侧最大偏差 `< 2e-4`。
- **通道分解恒等式** `ch_S1 + ch_S2 + ch_cov = ΔF₂`：21 城全部吻合（残差 `< 2e-6`），
  落盘的 `identity_resid` 字段全部 `≤ 1e-6`。
- **枚举 15,207 条**同样满足上述恒等式。

这些恒等式是模型定义决定的，与求解器、与稿件表述都无关，因此它们通过说明
**结果文件内部自洽**，不是"把同一个错数字抄了两遍"。

## 5. 核验中发现并已修正的问题

按严重程度排序。前两项是**稿件事实错误**，不是笔误。

1. **簇半径敏感性数字整体过期。** 稿件原文写"mean PoA 保持在窄带 $[1.026, 1.061]$"。
   用精确 Phase 2 重跑三档后实测为 **1.0688（0.8）/ 1.0376（1.0）/ 1.0267（1.2）**，
   带宽 0.0421，且随因子**单调**。旧值来自早期的近似 Phase 2 跑法，已替换。
2. **"重庆在 0.8 档超出求解时间限制被剔除"已不成立。** 该说明曾出现在稿件两处。
   加上 180 秒/城上限后，三档全部 21 城都达到 `Optimal`，无一被剔除。说明已删除。
   （北京在三档下规模相同——n=345、76 站——而 0.8/1.2 档都在 180 秒内证明最优，
   故加上限不改变 1.0 档的数值。）
3. **耗时声明严重偏低。** 文档原写 21 城精确跑"20–35 分钟"。实测单城（北京，无时间上限）
   已消耗 18 分钟 CPU 仍未结束；180 秒/城上限下全量约 1.5–2.5 小时。已改为实测值并说明
   上限不影响结论。
4. **数量级表述错误。** 稿件称并列与非并列两簇"相隔九个数量级"。实测
   最大并列 `|ΔF₂| = 2.8e-17`、最小非并列 `|ΔF₂| = 7.6e-6`，比值 `2.7e11`，即约
   **11 个数量级**。已改。
5. **复现说明中的位移量写错。** 原文"`F2_MILP` moves by 1.5e-5"——1.5e-5 是 `PoA` 的位移，
   `F2_MILP` 的位移是 7.0e-6。已改正并注明该配置编号。
6. **非并列配置计数不统一。** 复现清单写 12,495，稿件按 1e-12 口径为 12,494。已统一到
   稿件口径（两种口径下通道份额相同，见 §4）。
7. **校验脚本的"无法校验"被误读成"校验失败"。** 缺文件时原退出码为 1。现改为退出码 2
   并打印明确的 SKIP 语义与重生成命令（这些文件派生自受限栅格，按设计不分发）。
8. **`code/04_sensitivity/cluster_radius.py` 名不副实。** 它是早期规模探针：预算写死
   120 万/站（现行为 36 万），且依赖未分发的本地竞赛目录，不产出任何论文数字。
   已新增正式驱动 `cluster_radius_21.py`（封装 `exp1_21cities.py --cluster-factor`），
   文档指向新脚本，并在两处注明旧脚本的定位。

## 6. 最重要的发现：21 城 MILP 不是逐位可复现的

用文档命令从零单跑北京（`--limit 1 --phase2-time-limit 180`）得到
`PoA = 1.0646`，而稿件与存档文件是 `1.0644`。逐字段比对显示：

| 字段 | 存档 | 重跑 | 差异 |
|---|---|---|---|
| `nash_F1 / nash_F2 / nash_A1 / nash_S2 / nash_cov` | — | — | **全部逐位相同** |
| `milp_F1 / milp_cov` | 0.3642 / 0.364225 | 同 | **0** |
| `milp_A1` | 0.289461 | 0.289906 | 4.4e-4 |
| `milp_S2_weighted` | 0.349276 | 0.349140 | 1.4e-4 |
| `milp_F2` | 0.2719 | 0.2720 | 1.0e-4 |
| `PoA` | 1.0644 | 1.0646 | 2.0e-4 |

实例构造是确定的（Nash 侧、Phase 1、覆盖全部逐位一致，说明种子、几何、规模、预算
全都没变），抖动来自 **Phase 2 这个 MIP 本身**。

对北京同一实例进一步做求解器实验：

| 配置 | F2 | 备注 |
|---|---|---|
| HiGHS 单独，180 s | 0.27194244 | 与存档一致 |
| HiGHS 单独，180 s（另一次进程） | 0.27198081 / 0.27199053 | 与存档差 4e-5～5e-5 |
| HiGHS + CBC 备用（exp1 默认） | 0.27198081 / 0.27199053 | 同上有差异 |
| CBC 单独，180 s | **0.24937628** | 差 0.023，仍报 `Optimal` |

**根因定位（同进程连解 5 次，完全相同的设置）：**

```
solve 1: F2=0.27198081 status=Optimal
solve 2: F2=0.27198081 status=Optimal
solve 3: F2=0.27199053 status=Optimal
solve 4: F2=0.27199053 status=Optimal
solve 5: F2=0.27199053 status=Optimal
→ NONDETERMINISTIC: 2 distinct values, spread 9.712e-06
```

即：**同一个问题对象、同一套参数，HiGHS 在报告 `Optimal` 的前提下给出了两个相差
9.7e-6 的目标值。** 综合全部观测，北京 Phase 2 的 F2 至少出现过三个值
（0.27194244 / 0.27198081 / 0.27199053），跨度 4.8e-5。

原因：HiGHS 默认占用全部线程，并行 MIP 的剪枝/启发式顺序随机器负载变化。
尝试固定线程数的两条路都被本机 PuLP 3.3.1 + highspy 组合堵死：
`pulp.HiGHS(threads=N)` 会让求解器直接失败（连 2 变量玩具问题都返回
`Not Solved`）；`solverParams={"threads": N}` 抛
`setOptionValue(): incompatible function arguments`。**本环境没有受支持的方式
固定 HiGHS 线程数。**

**影响范围：**
- 单个城市的 PoA 有约 ±2e-4 的运行间抖动（第 4 位小数不稳定）；北京实测
  1.0644～1.0646。
- 21 城均值 1.0376 稳定到约 ±1e-4；论文的全部理论结论（PoA ≪ 1.667、排序、
  回归显著性）不受影响。
- 稿件把单城值写到 4 位小数，这个精度**没有求解器层面的保证**。
- `fallback="cbc"` 曾是安全隐患：CBC 在此模型上会大幅跑偏却同样报告 `Optimal`。

**已采取的代码处置：** `phase2_exact` 的备用求解器逻辑已改为"只接受更好的结果"——
记录每次尝试的目标值并快照变量值，只有严格优于此前最佳时才替换；主求解器一旦返回
`Optimal` 立即停止，不再让 CBC 覆盖。这消除了"备用求解器把结果弄差"的风险，
但**不能**消除 HiGHS 本身的并行非确定性（那需要能固定线程数，本环境做不到）。

## 7. 尚未闭环的一项

**21 城逐城从零重跑。** 已用文档命令完成北京单城（§6），结论是"实例确定、
求解器有 ±2e-4 抖动，且已用同进程连解 5 次直接证实非确定性"。要拿到全部 21 城的
确定性数值需要整批重跑（180 s/城上限，约 1.5–2.5 h），未执行；且即便重跑，
只要线程数固定不了，结果仍会带这个量级的抖动。

另需注意：主结果文件（`21cities_exact_locked.json` 等）**不在 git 中**
（`.gitignore` 排除 `results/main/*`），因为它们派生自受限的 Han et al. 栅格。
这是有意的合规边界，代价是全新克隆无法直接运行校验脚本——已通过退出码 2 的
SKIP 语义缓解。

## 8. 结论

- **枚举层面：完全可复现。** 300 条 smoke test 逐位一致；θ=0.60 与主枚举 15,207 条
  零差异；不同求解器 gap 容差下仅 1 个 near-tie 配置有 7e-6 级别浮动。
- **图表层面：完全可复现。** 包内脚本重绘与论文图逐字节一致。
- **稿件数字：109 项全部对上**，且核验过程中发现 2 处稿件事实错误（簇半径带、
  重庆剔除）、1 处耗时失实、3 处数量级/计数/位移量表述错误，均已修正。
- **21 城层面：结构与回归完全可复现，单城数值有 ±2e-4 求解器抖动。**
  这是本次核验最重要的发现，也是唯一未能闭环的环节。

实验脚本与原始日志保存在 `results/_verify/`（`test_repeat.py` 是同进程连解 5 次
的确定性实验，`test_solver_paths.py` 是求解器路径对比，`test_gap_attribution.py`
是 gap 容差归因；`enum_300.json` 与各 `repro_beijing_*.json` 是对账产物）。
